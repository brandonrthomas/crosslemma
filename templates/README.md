# Templates

Forms only, with no problem in them. `bin/new-workspace` copies the ones an instance starts with and fills the
`@TOKENS@`; the rest are copied by hand when the moment comes (an attack, an audit, a packet). A `⟨slot⟩` is
filled by whoever writes the file; `bin/lint-brief` refuses a brief that still has one.

| file | what it is | filled by |
|---|---|---|
| `PROBLEM.md` | the problem statement: status marks, the statement, what a result looks like, self-checks, variants a proof must not exclude, tests for any argument | the user, at the start; the orchestrator edits only on the user's word |
| `prior-art.md` | the register of sources this workspace has itself opened, and the Leads it has not | the orchestrator, one entry per source read |
| `attacks/README.md` | one attack: idea, why, why not, milestones, exit criteria, kill criteria, status, history | the orchestrator, before the first run of the attack |
| `DIRECTION.md` | a direction brief: the question with no shapes in it, filters, candidate mechanisms, the author's ranking to be attacked, disclosure; corrected later by dated header notes, never by editing the body | the user or an outside model; header notes by the orchestrator on the user's word |
| `HANDOFF.md` | the pointer sheet, with the preflight and the required opening prompt | every session, at its end; `new-workspace` writes the first |
| `intake-record.md` | one outside input's record (`intake/IN-NNN-slug/record.md`): where it came from, its author family, what it had seen, each item's class as ruled, who has seen it | the orchestrator, on receipt, before anything acts on the input |
| `analyst-prompt.md` | a session prompt for the user's analyst on one instance: role outside the trust chain, as operator agent if the user designates it, hard rules, audits, records; an appendix for a Clatter channel the user opens and closes | the user, by hand, when they want an analyst |
| `orchestrator-prompt.md` | a session prompt for an instance's orchestrator: start, purposes, the approval gate, runs, claims, outside input, records; the same appendix from the other side | the user or the outgoing session, beside the handoff's opening prompt |
| `runs/README.md` | which briefs are generated by `bin/new-run` and which come from here | — |
| `runs/restatement-BRIEF.md` | a claim restated with the wording its artifact certifies, on byte copies, no worker | the orchestrator, on the user's approval of the sentence as text |
| `runs/repair-BRIEF.md` | the task sections of a run that repairs a check and states exactly what it certifies | the orchestrator, over a `--role solver` skeleton |
| `runs/canary-BRIEF.md` | the context and sandbox canary, one per route the instance enables | `new-workspace` for run 001; by hand for each further route |
| `runs/PROVENANCE.md` | the record of a run with no worker, or of an outside run: why, the packet, what left the machine, the outcome | the orchestrator, after the run |
| `runs/outside-reader-BRIEF.md` | the packet for one stuck question, sent to a party with no stake | the orchestrator, after the second gap on one sentence |
| `runs/setup-audit-BRIEF.md` | an outside audit of a solver run's set-up before it is launched | the orchestrator, when the brief carries a new relaxation, list or transcription |
| `runs/handoff-audit-BRIEF.md` | an outside fidelity check of a handoff against the record | the orchestrator, when the operator calls one |

Nothing here is a claim, and no template names a claim id, a run number or a result. A worked example in an
instance is that instance's own (→ `LESSONS.md` "A duplicated scaffold carries the sibling's examples").
